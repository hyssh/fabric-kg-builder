#### B2: Correction Flow — interactive init-domain allows edit before approval

**Implementation:**

1. **Three-Choice Approval Prompt** (`init_domain_cmd.py`)
   - `Approve [y], Correct [c], Abort [n]`
   - Triggered after profile render
   - User can choose to approve, edit, or abort

2. **Correction Editing Fields** (`_apply_corrections()`)
   - Document categories (comma-separated list)
   - Entity candidates (comma-separated list)
   - Extraction risks (clear-all option)
   - Observed date range (range entry, e.g. `2001,2024`)
   - Each field editable in place

3. **Loop Behavior**
   - After corrections, re-render profile
   - Re-ask approval question
   - User may correct multiple times
   - Continue until Approve or Abort

4. **Provenance Tracking** (`user_corrected: bool` on SourceProfile)
   - Set `True` when any correction field changed
   - Used in `_build_contract_from_profile` logic
   - Inferred entities/categories → domain.yaml **only when `user_corrected=True`**
   - Auto-approved profiles leave TODO placeholders (not heuristic-driven)

5. **Deterministic/Noninteractive Path**
   - `--approve` flag bypasses all correction prompts
   - Non-TTY stdin (CI/CD) bypass corrections automatically
   - `user_corrected` stays `False` in both cases
   - `sys.stdin.isatty()` + `--interactive` flag for forced TTY simulation
