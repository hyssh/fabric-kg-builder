### Issue #13: Example Gating — Required-Empty Blocked, Optional-Absent Omitted
**Requirement:** Gate few-shot examples on observed relationship row counts. Required factual examples need positive rows; block required-unavailable, omit optional-unavailable.

**Implementation:**
- `gate_competency_examples(contract, availability, *, min_required_rows=1)` pure function (owner: `knowledge/validation.py`)
- Classifies relationships into 4 states via `classify_relationship_availability`:
  - `schema_supported_unobserved` ⟵ status="not_observed"
  - `optional_absent` ⟵ status ∈ {unavailable, insufficient} AND not required
  - `required_absent` ⟵ status ∈ {unavailable, insufficient} AND required
  - `executable_nonempty` ⟵ status="sufficient" (observed_rows > 0)
- `graph_few_shots_from_competency_contract` uses receipts to filter optional-absent cases (published=False → skip)
- Raises `DataAgentRequiredExampleEmpty` for required-absent (caught at CLI boundary)
- Extended `QueryReadiness` with `observed_relationship_rows: dict[str, int]` for per-relationship capture

### Issue #14: Property Preservation — Selected Properties Not Stripped, Validated Against Requirement
**Requirement:** Preserve Fabric-supported Graph property selection through the public draft and publication. Validate example property refs against persisted/draft/published. Compare published against the *original semantic requirement*. Report required/compiled/draft/published counts + hashes.

**Implementation:**
- **Property representation:** `build_public_graph_source_projection` no longer strips `children` from elements; projects selected, `agent_visible` property children into Fabric shape

- **Extended receipt fields:**
